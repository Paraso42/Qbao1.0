# Qbao 环境与网络地图（开发 / 内测 / 生产）

> 面向**非网络专业读者**的环境说明书：几个网址分别是什么、给谁用、改代码先上哪、为什么有时"看不到新版本"。
> 按隐私铁律，本文所有真实地址一律用占位符：{DOMAIN} 生产域名、{BETA_HOST} 内测域名、{ORIGIN_IP} 源站 IP、{HK_IP} 香港中转服务器 IP、{SSH_USER} 服务器用户。
> 真实值对照表只保存在本机 gitignored 的 `local/ENV.md`（部署/发布纪律见 [DEVELOPMENT_FLOW.md](DEVELOPMENT_FLOW.md)，服务器细节见 [DEPLOY.md](DEPLOY.md)，游戏 QA 见 [GAMES.md](GAMES.md)）。

## 1. 一句话概括

Qbao 有三层"环境"，改动一律**从左到右**流动：

```
本机写代码(L0) → 内测环境验收(L1) → 生产上线(L2) → 推送 GitHub
```

- **L0 本机**：写代码、跑单测、浏览器里快速看效果（不联网、不碰任何用户数据）。
- **L1 内测**：一台与生产一模一样的"影子服务器"，**独立数据库 + 独立端口 + 独立网页目录**。所有测试动作（注册小号、对局、兑换、清库）都只发生在它身上，真实用户完全不受影响；同学/朋友内测也走这里。
- **L2 生产**：真实用户使用的网址。只接收"内测验收通过"的改动；上线后只做**只读**巡检，绝不拿生产库做测试。

## 2. 概念卡片（用生活类比）

| 名词 | 是什么 | 类比 | 在本项目的角色 |
|---|---|---|---|
| 域名 | 人类可读的网址 | 门牌号 | {DOMAIN}（生产）、{BETA_HOST}（内测） |
| DNS | 把域名翻译成服务器 IP | 电话簿 | 由 Cloudflare 托管，指向香港中转服务器 |
| Cloudflare | 全球 CDN + DNS | 快递总站 | 加速静态资源、DNS 管理、对外 HTTPS 入口 |
| 反向代理（Caddy） | 收下 HTTPS 请求并转发到源站 | 前台柜员 | 香港中转服务器上的 Caddy：负责 TLS 加密与转发 |
| 源站 nginx | 真正存放网页文件、转发 API 请求的服务器 | 仓库管理员 | 源站服务器 {ORIGIN_IP}：静态文件直出 + /api 转发 |
| Node API | 处理业务逻辑的程序 | 业务员 | 源站上的 Express 服务（生产 :3000 / 内测 :3100） |
| PostgreSQL | 数据库 | 账本 | 生产库 qbao / 内测库 qbao_beta（同一个数据库软件里的两本账） |
| 缓存 | 浏览器/CDN 暂存文件以加速 | 复印留底 | 生产静态资源保留 7 天，改版靠"版本号参数"刷新 |
| WebSocket | 双向长连接 | 对讲机 | 狼人杀房间实时通信（:3011） |
| HTTPS | 加密的网页传输 | 密封信封 | 生产与内测都走 HTTPS；源站直连 IP 为 HTTP |

## 3. 拓扑（数据流图）

```
【生产 · 真实用户】
  用户 ──https://{DOMAIN}──> Cloudflare（CDN/代理）──> 香港中转 {HK_IP}（Caddy，TLS 终结）
        ──http://{ORIGIN_IP}──> 源站 nginx（两个入口到同一个源站 = 同一份数据）
                                             ├── 静态文件 /home/qbao/qbao/app（7 天缓存）
                                             ├── /api ··· → Node :3000 → PostgreSQL 库 qbao
                                             └── 狼人杀 ··· → Node :3011（房间在内存，不落库）

【内测 · 测试/内测人员】
  内测者 ──https://{BETA_HOST}──>（DNS 直连，不过 CDN）香港中转 {HK_IP}（Caddy 按主机名分流）
        ──> 源站 nginx（按 Host 头识别内测域名）──> 静态 /home/qbao/qbao-beta/app（不缓存）
                                             └── /api ··· → Node :3100 → PostgreSQL 库 qbao_beta
```

关键点：**生产两个网址是同一个源站同一个账本**（域名走中转，IP 是直连），所以数据一致；
**内测是完全独立的第二套"静态目录 + API + 账本"**，两边互不碰面。

## 5. 隔离纪律（"测试"与"用户使用"如何分开）

1. **数据隔离**：测试账号只存在于 qbao_beta；生产库禁止任何测试写入（对局/兑换/领奖/删改）。
2. **服务隔离**：内测 API（:3100）与生产 API（:3000）是两个进程、两本账本；改坏内测只影响内测。
3. **代码同步顺序**：新代码先同步到内测目录并重启内测服务 → 冒烟 → 验收 → 才同步生产目录。
4. **数据库迁移顺序**：同一迁移文件**先在内测库跑、验收后在生产库跑**（每本账本独立记录已应用版本）。
5. **自动化 QA 钩子门禁**：游戏页 `?qa=1` 调试钩子只在 {BETA_HOST} 与 localhost 生效，生产域名一律忽略（代码层强制，见 docs/GAMES.md 第六节）。
6. **生产只读巡检**：每次生产上线后，用金丝雀账号跑 health/登录/GET 断言，不产生任何写操作。
7. **缓存纪律**：生产静态缓存 7 天 → 网页文件里引用 js/css 必须带版本号参数（?v=…）才能让老浏览器拿到新版本；内测不缓存所以没有这个问题。
8. **内测服全员管理员（AUTO_ADMIN=1）**：内测环境注册即管理员，便于测试管理功能；配套防互害保护——管理员账号不可被其他管理员封禁、重置密码或改变角色（服务端强制），角色变更只能由后台脚本完成。正式环境严禁开启该开关，正式服管理员只能由后台脚本授予。
9. **数据互导通道**：正式服/内测服「设置 → 数据 → 本地备份」下载的 JSON 可在两个环境间互相导入（目标环境先用同一账号注册登录，再「上传恢复」）；备份仅包含学习数据，**管理员身份与封禁状态属于账号属性，不随备份迁移**，任何环境都无法借备份转移解除封禁或获得管理员。

## 6. 一次改动的完整旅程（新流程）

以"调整弹珠兑换规则"为例：

```
1) 本机改代码 + 补/改单测 → DoD 全绿（L0）
2) 运行同步脚本：server 代码 → 内测目录；执行内测库迁移；重启内测 API（L1）
3) 内测自动冒烟：注册→登录→兑换→对局，断言写进 qbao_beta 且 qbao 零变化
4) 你在 https://{BETA_HOST} 上点一遍验收（或发给内测同学）
5) 验收通过 → 同样步骤执行到生产（同步、迁移、重启）→ 生产只读巡检
6) 你明确说"测试通过" → git push + tag + Release
```

任何一步失败就回到上一步修，**生产上永远只有验收过的版本**。

### 7.1 手机壳"内测版"（已落地 2026-09-08）

- 构建：`scripts/build-beta-apk.ps1`（产物 .tmp/beta-apk/Qbao-Android-1.0.1-beta.N.apk）。壳工程支持环境变量覆盖与 gradle `-PqbaoBeta` 切换：应用标识 com.qbao.beta、应用名"Qbao 内测"、指向内测域名，与正式版**同签名共存安装**、数据互不干扰。
- 发布：`publish-mobile.js add --channel beta`（记录 channel=beta；stable 默认纪律不变）。
- 用户入口（**自选、非强制**）：下载页 /dl 与网页「设置 → 下载中心」Android 区自动出现"内测版（可选）"区块（徽标 Beta/内测最新），正式版区域不受影响。

## 8. 常见问题（FAQ）

**Q1 为什么 https://{DOMAIN} 和 http://{ORIGIN_IP} 数据一样？**
中转服务器只负责"传话"，两个入口最终都到同一个源站、同一个数据库，所以账本自然一样。

**Q2 为什么不直接都用一个网址？**
域名更稳定、可上 HTTPS、可套 CDN；IP 直连作为无域名兜底与旧版兼容入口，两者长期并存。

**Q3 我改了代码，为什么网站上还是旧的？**
三种可能：(1) 只改了本机，没同步到服务器；(2) 生产静态缓存 7 天——网页引用的 js/css 必须换版本号参数 ?v= 才会让浏览器拉新版（或强刷 Ctrl+F5）；(3) API 改动后没有重启对应服务。

**Q4 为什么改数据库要"先内测后生产"？**
迁移文件要在内测库先跑一遍验证无误（幂等、可重试），再去生产库执行；两边各自记账，互不干扰，任何一边失败都可单独重试。

**Q5 内测环境会不会被真实用户访问到？**
内测网址只有受邀者知道；且它连的是独立账本，即使被访问也只是多一个测试账号，不影响生产。真担心可加访问限制（预留开关）。

**Q6 为什么跑测试要开 VPN？**
VPN 只用于两件事：访问 GitHub 推送代码、登录 Cloudflare 控制台改 DNS。日常打开内测/生产网址不需要 VPN。

**Q7 游戏里的"QA 钩子"是什么？**
游戏移植时内置的自动化测试入口（模拟登录、自动点按钮），用于冒烟；出于安全它只在 {BETA_HOST}/localhost 放行，生产域名下即使拼了参数也会被忽略。

**Q8 内存这么小，跑两套服务会不会崩？**
内测 API 与生产 API 是同一台源站上的两个 Node 进程。已预留降载开关（内测不开 AI 任务）；若内存吃紧，最坏回退方案见 docs/DEPLOY.md 4B 的"预案"小节。

**Q9 内测环境怎么知道当前是哪个版本？**
内测页随每次同步即时更新，无缓存；页面顶部有"内测环境"角标。版本号以 `server/package.json` 与 CHANGELOG 为准。

## 9. 术语表

| 术语 | 解释 |
|---|---|
| L0 / L1 / L2 | 三层环境：本机 / 内测 / 生产 |
| 源站 | 真正运行服务的服务器（相对 CDN/中转而言） |
| 回源 | CDN 或中转把请求转发给源站的过程 |
| TTL | DNS 记录存活时间（改动域名记录后等待生效的时长） |
| 金丝雀账号 | 只读巡检用的专用账号（类比"矿工的金丝雀"先探路） |
| 幂等 | 同一操作执行多次结果一致（迁移脚本可安全重跑） |
| CAS | 读-改-写带版本比对，防并发覆盖 |
| singlefile | 前端构建产物：一个 index.html 内嵌全部 js/css |
